# v0.1.0 — Torn Forum Command Center, implementation plan

Spec: `docs/superpowers/specs/2026-08-07-torn-forum-command-center-design.md`.
Read it first; where the two disagree, the spec wins and this plan is amended.

Tests are written before the code they check, and each task ends green before
the next begins. `npm test` and `npm run test:syntax` must pass at every task
boundary.

## Files in scope

| File | Responsibility |
|---|---|
| `torn-forum-command-center.user.js` | The whole distribution: metadata, engine, runtime |
| `tests/load-userscript.js` | `vm` harness — reads the source, injects exports in memory only |
| `tests/*.test.js` | One suite per contract, listed per task |
| `package.json` | `test`, `test:syntax` scripts, no runtime dependencies |
| `docs/architecture.md` | Rewritten from the scaffold placeholder |
| `docs/qa-checklist.md` | The signed-in manual gate |
| `README.md` | Install, features, privacy, limitations |
| `CHANGELOG.md` | One `0.1.0` entry, written at release |

No other file is in scope without amending this plan.

## Task 1 — Harness, metadata, and the page guard

**Symbols:** metadata block, `SCRIPT_VERSION`, `isForumsPage`, `parseForumRoute`

- Adapt `tests/load-userscript.js` from the Education Scheduler: deterministic
  timers, a mock `Date`, a GM store, an injectable `location`, listener
  registries for `window` and `document`, and the VM-realm prototype transform.
- Add adapter stubs the Education Scheduler did not need: `GM_xmlhttpRequest`
  and `PDA_httpGet`, each individually presentable or absent, so tier selection
  is testable.
- `tests/metadata.test.js`: exact `@match`, exactly the three `@grant` values,
  exactly one `@connect` (`api.torn.com`), `@run-at document-end`, no
  `@downloadURL` or `@updateURL`, `@version` equal to `SCRIPT_VERSION` and to
  `package.json`.
- **ASCII gate:** the source contains no character outside 0x09–0x7E. This is
  the regression that killed the Education Scheduler on Torn PDA; it fails the
  build, not a review.
- `tests/route.test.js`: the guard table — accept `www.torn.com/forums.php` with
  any query or hash; reject another path, another host including a suffix-spoof
  host, and a missing or hostile `location`, without throwing.
- `tests/hash.test.js`: parse `p`, `f`, `t` from both `location.hash` and
  `location.search`, tolerate a leading `#` or `#/`, missing params, and junk;
  return a frozen `{view, forumId, threadId}` with `null` for absent values.

## Task 2 — Storage keys, normalisers, and independent recovery

**Symbols:** `STORAGE_KEYS`, `normaliseSettings`, `normaliseOrganizer`,
`normaliseDrafts`, `normaliseFeed`, `normalisePostCache`, `loadKey`, `saveKey`

- `tests/storage.test.js` first: each key round-trips; a corrupt value in one
  key resets only that key and returns a named recovery reason; an unknown
  future schema version is refused rather than coerced; a write that throws
  (quota) surfaces a save error instead of being swallowed.
- Every normaliser is pure, total, and takes the raw stored value plus a
  `now`. It never throws and never returns a partially-valid object.
- `tfcc:key` is stored and read through helpers that validate the 16-character
  key shape and never log the value.

## Task 3 — The API adapter and the rate limiter

**Symbols:** `httpGet`, `tornApiGet`, `RateLimiter`, `redactUrl`,
`mapTornError`, `PDA_KEY_SENTINEL`, `pdaInjectedKey`

- `tests/api.test.js` first:
  - tier order — `PDA_httpGet` beats `GM_xmlhttpRequest` beats `fetch`, and
    each tier alone works;
  - the adapter never rejects: network throw, non-2xx, non-JSON body, Torn error
    envelope and timeout all resolve to `{ok:false, reason, detail}`;
  - the 15 s timeout is a timer race that clears its timer, and a late settle
    after timeout neither redraws nor creates an unhandled rejection;
  - Torn error codes 2, 5 and 13 map to distinct named messages;
  - **redaction**: no key reaches any `detail`, and `redactUrl` strips the whole
    query string.
- `tests/ratelimit.test.js`: the 650 ms minimum gap and the 40-per-60 s ceiling
  hold under a fake clock; a request over the ceiling resolves `throttled`
  rather than queueing without bound; single-flight drops a concurrent duplicate
  instead of issuing it.
- `PDA_KEY_SENTINEL` is assembled from three fragments at runtime so Torn PDA's
  source substitution cannot rewrite the comparison. A test asserts the literal
  slot appears exactly once in the source and that a replaced slot is detected.

## Task 4 — The engine: merge, unread, sort

**Symbols:** `mergeThreads`, `resolveLastActivity`, `unreadFor`, `SORT_MODES`,
`sortThreads`, `catchUpList`

- `tests/unread.test.js`: `effectiveUnread`, dismissal via `lastSeenTotal`,
  re-emergence when `posts.total` grows, and the catch-up predicate.
- `tests/sort.test.js`: every sort mode, pinned always first, stable tie-breaks,
  unknown last activity always last and never treated as zero.
- `tests/merge.test.js`: the last-activity precedence chain in order, the
  `source` label each row reports, an unsubscribed thread retaining its notes
  and moving to an unsubscribed state, and a thread known only from local
  capture appearing with no API row.
- `tests/purity.test.js`: the engine section, comments stripped, contains no
  reference to `document`, `window`, `location`, `fetch`, `GM_`, `PDA_`,
  `Date.now` or `new Date()`.

## Task 5 — Query parsing and search

**Symbols:** `parseQuery`, `matchThread`, `matchPost`, `searchMetadata`,
`searchPosts`, `buildNativeSearchUrl`

- `tests/search.test.js` first: bare terms, `"quoted phrases"`, `by:`, `tag:`,
  `folder:`, `is:unread`, `is:pinned`, leading `-` negation on every term type,
  unknown prefixes treated as literal text, and an empty query matching
  everything rather than nothing.
- Matching is case-insensitive and diacritic-naive on purpose; it is documented
  as such rather than half-implemented.
- `buildNativeSearchUrl` produces Torn's own search URL and percent-encodes the
  query. A test pins the exact shape and asserts it is a `www.torn.com` URL.

## Task 6 — The post cache

**Symbols:** `postCacheAdd`, `postCacheEvict`, `postCacheSize`, `stripHtml`

- `tests/postcache.test.js` first: LRU eviction by thread, the 2000-post
  ceiling, the serialised-size ceiling, that eviction never leaves a partial
  thread, and that a cache exceeding both caps converges in one pass.
- `stripHtml` is pure and defensive: it removes tags and decodes the five XML
  entities without constructing a DOM, because the engine may not touch one.

## Task 7 — Folders, tags, pins, priority, drafts

**Symbols:** `folderFor`, `applyAutoAssign`, `toggleTag`, `setPriority`,
`saveDraft`, `draftFor`, `pruneDrafts`

- `tests/organizer.test.js`: auto-assign by `forum_id` from
  `/forum/categories` data, manual assignment beating a rule, tag add/remove
  idempotence, priority clamping to −2…+2, and folder deletion moving threads to
  Unfiled rather than orphaning them.
- `tests/drafts.test.js`: save, load, overwrite, empty-string deletion, and the
  size cap. The React native-setter insert path is a runtime concern and is
  tested in Task 9.

## Task 8 — Export and import

**Symbols:** `EXPORT_PREFIX`, `encodeState`, `decodeState`, `importPlan`

- `tests/share.test.js` first: round-trip fidelity; the key and post cache are
  absent from every export; a wrong prefix, a wrong version, truncated base64,
  a non-object payload, an oversized payload and a payload with hostile keys are
  each rejected with a distinct named reason and apply nothing.

## Task 9 — Runtime: mount, panel, capture, drafts insertion

**Symbols:** `whenDocumentReady`, `observeNavigation`, `findMountPoint`,
`renderPanel`, view renderers, `captureVisit`, `findReplyBox`, `insertDraft`

- `tests/navigation.test.js`: `body` and `documentElement` absent at evaluation
  and added later with no navigation event still mounts exactly once; injection
  after `DOMContentLoaded` and `load` still starts via the poll; all readiness
  paths firing together produce one observer and one panel; leaving
  `forums.php` unmounts; a hash change within forums does not remount.
- `tests/panel.test.js`: the loading shell renders before any request; each of
  the five views builds a complete model; a failed refresh shows a named error
  with a retry, never a blank panel; the mount falls back to
  `#tfcc-fallback-mount` when no container is connected, and never stacks two.
- `tests/capture.test.js`: a thread route records `lastVisitedAt`, title and
  forum id from `location` and `document.title` only; a malformed title is
  stored as-is rather than guessed; capture never writes on a non-thread route.
- `tests/drafts-insert.test.js`: `insertDraft` uses the native
  `HTMLTextAreaElement.prototype.value` setter and dispatches a bubbling
  `input` event; with no textarea found it reports the copy fallback instead of
  throwing.
- `tests/style.test.js`: both theme blocks define every token they use; no
  black text on a dark background; the takeover rule constrains width to the
  viewport and height with `100vh` then `100dvh` with internal scrolling; a
  narrow-width rule exists; `:focus-visible` is styled.

## Task 10 — Debug report and first-run

**Symbols:** `gatherDebugContext`, `buildDebugReport`, `firstRunModel`

- `tests/debug-report.test.js`: the report contains version, platform tier,
  route, counts and the last error reason — and **never** the API key, a post
  body, a draft, a note, or a raw API response. The assertion is written as a
  denylist scan over the whole rendered report, not a spot check.
- First run with no key renders a key prompt and issues no request.

## Task 11 — Whole-system verification

- `npm test`, `npm run test:syntax`, `git diff --check`.
- **Mutation check.** For each user-visible promise, break it and prove the
  matching test fails for the promised reason: change `@run-at` to
  `document-idle`; insert one typographic quote; remove the DOM wait; remove the
  redaction; remove the rate limiter; remove the `100dvh` override; move the
  first request ahead of the loading draw.
- Write `docs/architecture.md`, `docs/qa-checklist.md`, `README.md`, and the
  `0.1.0` `CHANGELOG.md` entry.
- Generate `docs/code-map.md` with `/code-map`.

## Task 12 — Signed-in manual QA gate

Automated tests cannot prove Torn PDA's injection or Torn's live API. Both
matrices in `docs/qa-checklist.md` must pass on the same build before release.

## Stop conditions

Stop and amend this plan before proceeding if any of these becomes necessary:

- widening `@match`, adding a `@grant`, or adding a `@connect` host;
- any request that is not one of the five endpoints in the spec;
- any write request to Torn;
- depending on a Torn CSS class or DOM structure for **data** rather than for
  mounting or the reply box;
- storing the API key anywhere but `tfcc:key`, or including it in any output;
- exceeding the stated request budget per refresh.

## Completion gate

Complete when every suite passes without weakened assertions, the mutation
checks fail for their promised reasons, the security and storage diff audit is
clean, and both signed-in QA matrices pass. Release is blocked on the owner's
real-device checks.

## Handoff log

### 2026-08-08 — v0.1.0 built, blocked on the signed-in QA gate

**Branch and what merged.** All work is on `main`, 18 commits, no remote and no
PR. Tags `v0.1.0-rc3` through `v0.1.0-rc6` mark the compliance and live-bug
rounds. There is nothing to merge; the repo has never had a second branch.

**What shipped.** The whole of v0.1.0: `torn-forum-command-center.user.js`
(150K, one IIFE, engine and runtime), 20 test suites, `tests/load-userscript.js`
(the `vm` harness), `tests/mutation-check.mjs`, `tests/render-preview.mjs` and
`tests/contrast-audit.mjs`. Tests went 0 to **301**, plus 50 mutations all
confirmed to bite. Docs: `README.md`, `docs/architecture.md`,
`docs/rules-compliance.md`, `docs/qa-checklist.md`, `docs/adr/0001-*`,
`docs/code-map.md`, `docs/reference/`.

**What the plan got wrong.** Each of these is corrected in the code and **must
not be reverted**:

- The plan assumed the panel could render by replacing its own `innerHTML`
  freely. It cannot. `observeNavigation` watches `documentElement` with
  `subtree: true` and the panel is inside that subtree, so every render
  scheduled another one at the debounce interval. No text box could hold a
  caret and clicks landed on replaced nodes. Three guards now exist -
  `isOwnMutation`, the identical-render skip, and the focus deferral - and the
  first two overlap deliberately. **Do not revert; do not "simplify" by removing
  either structural guard.**
- The plan said a Minimal-access key. Torn's key page does not offer Minimal as
  a choice. The panel names the selections instead: a Custom key with
  `forumsubscribedthreads` and `forumfeed`, or Limited Access. **Do not
  reintroduce a preset name as the requirement.**
- The plan had no key-rejection policy. Torn's API terms require removing a
  disabled or invalid key on error and name a temporary IP ban as the penalty.
  Codes 2, 13, 16 and 18 now stop the key being used, persisted across reloads.
  Codes 5, 9, 10, 11 and 17 deliberately do **not** condemn the key.
- The plan treated `state.generation` as sufficient staleness protection. It was
  never incremented, so the guard was dead and a mid-refresh reset was silently
  undone. `invalidateInFlight` now exists and `refreshAll` checks before every
  write. **Do not** call `invalidateInFlight` from `rejectKey`: doing so made
  the refresh treat its own rejection as stale and swallow the message.
- `autosaveDrafts` and `hideTornBox` were specified and never implemented. Both
  now are. Autosave must never write an empty box over a saved draft.

**What was discovered.**

- Torn's scripting rule and API acceptable usage terms are quoted verbatim in
  `docs/rules-compliance.md`. `rules.php`, the wiki and the API docs all refuse
  automated requests and Cloudflare blocks at the origin, so proxies and
  archives fail too. The API docs page is saved at
  `docs/reference/torn-api-docs-2026-08-08.html`; the scripting rule was
  supplied by the owner and no copy of that page exists.
- Torn's documented limit is 100 requests per minute across all of a user's
  keys. This script self-limits to 40.
- CSS inheritance is the weakest source: a bare `td { color: #000 }` on Torn's
  stylesheet beat the panel's inherited color and painted the API key table
  black. `background` needs its own reset because it is not inherited at all.
  `tests/render-preview.mjs` now renders every view a second time under a
  hostile host stylesheet; the plain previews were too clean to catch either.
- Torn PDA ignores `@match`, rewrites typographic quotes across the source
  before injection, and substitutes `###PDA-APIKEY###`. All three are tested.
- The `vm` harness has three cross-realm traps, all fixed and commented:
  injecting main-realm intrinsics, unwrapped methods on returned objects, and
  unwrapped exported arrays. A fourth gap - `innerHTML` not firing observers -
  is why the redraw loop shipped.

**What is still open, and it needs a human.**

`docs/qa-checklist.md` has never been walked. Nothing in it can be automated:
it needs a real Torn account, a real API key and a real device. Release is
blocked on it. The highest-value items are the Interaction section (the redraw
regression), revoking a key mid-session to prove no further requests are made,
and Match Torn following Torn's own theme toggle.
